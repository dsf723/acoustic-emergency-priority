# 救护车警笛识别：当前阶段与采集流程

## 当前已有结果

- 已部署仅警笛候选模式，关闭拍手/普通声音输出；定位与类别的置信度分别处理。
- 规则、OLED和目标输出回归通过；这不代表已经能区别救护车/警车/消防车。
- 第一段16.1秒阵列实录已保存，块号连续且可用采集错误计数无增量。
  但没有清楚匹配到参考音频，需重录，暂不进入训练集。
- 参考音频 `制片帮素材_188809_救护车的警笛声免费音效.mp3`，source-id为
  `zhipianbang_188809`；同一文件换方向、距离或音量重录仍使用同一source-id。

## 接下来逐步做

1. 手机/外接音箱暂停，先保存一段安静背景，确认底噪和采集链路。
2. 手机将参考警笛设为单曲循环；音箱在0°约1米，阵列位置应清楚可闻。
   连续录满16.1秒，再对比频谱、声级和参考片段；不能只根据文件标签认为录到了目标。
3. 先换方向和音量验证这一个参考音源的识别、漏检和角度。它们只用于开发，不能冒充独立测试来源。
4. 增加不同来源的救护车警笛；分别采警车、消防车、喇叭、说话、音乐、背景声作为非目标。
5. 数据复核后，电脑建立目标/非目标分类基线；按原始source-id隔离训练、验证、测试，
   再考虑小模型部署ARM以及FFT/互相关等运算迁移FPGA。

## 样本验收

- `metadata.json` 的 `status=complete` 仅为录音结构和可用错误计数检查通过。
- 声音类别由人工提供，必须听音/频谱复核，额外标记content_review_status。
- 拒收不完整、间断或错误计数新增的采集；低信噪比样本先判断标签是否仍可辨，再决定训练用途。
- 同一个MP3的不同片段、重录、增强副本全部属于同一个来源组。
- 识别报告应给独立来源的误报、漏报、检测延迟；角度错误单独统计。
- 多声源下，“检测到警笛”与“确定该警笛方向”是两件事，当前单主声源定位未实现源分离关联。

## 已知限制

当前规则不能保证区分救护车/其他警笛；触发后变为连续稳频音的失效退出仍需补充验证与改进。
现阶段不宜仅降低SNR门限来掩盖采音信号弱的问题，也不应据合成数据报告实测准确率。
